# Task Plan: Phase 4 - Result-Set Parity

## Phase Summary

**Phase:** Phase 4 - Result-Set Parity

**Status:** Complete

**Goal**

Move final result generation onto the same composed anchor model so filtering and result projection are feature-wise on par with the legacy engine.

**Focus**

- define the handoff from composed anchor sets to result projections
- migrate the key result-set formats used by the API
- validate result payloads and SQL shape against legacy behavior where equivalence is required
- preserve the separation between filtering, facet content generation, and final result projection

**Acceptance Criteria**

- [x] The main result-set formats used by the API can be generated from composed anchor sets.
- [x] Result generation on the composed path matches legacy behavior for validated scenarios.
- [x] The runtime no longer depends on legacy filtering internals to generate equivalent results for supported requests.

## Documentation Targets

- Maintain the result-projection row in `docs/proposals/done/QUERY_ENGINE_OVERHAUL/PARITY_INVENTORY.md`.
- Record durable result-projection and handoff changes in `docs/DESIGN.md`.
- Update this task plan in place as result parity widens or explicit exceptions are accepted.

### Core Result Runtime Migration

**Objective**

Move `ResultService` onto composed anchor sets while keeping unsupported result requests explicit.

- [x] Introduce the initial result-projection runtime path that consumes an explicit handoff object before SQL compilation.
- [x] Widen that runtime path so supported result requests use composed anchor sets instead of the legacy query-setup fallback.
- [x] Keep `LoadResultService` and `ResultController` as thin API handoff layers rather than moving result-projection logic into the API boundary.
- [x] Preserve explicit legacy routing or fallback for unsupported result requests until parity is proven.
- [x] Add focused unit coverage around runtime selection, unsupported boundaries, and payload construction.

**Completion Criteria**

- [x] Supported result requests can be generated from composed anchor sets without relying on legacy filtering internals.
- [x] Unsupported result requests still fail or fall back explicitly rather than silently mixing legacy and composed behavior.

## Scope

**In scope**

- moving final result generation onto the composed anchor model for the active API result formats
- explicit exception handling for result formats or payload behavior that still cannot satisfy the current composed contracts
- focused unit, service, live, and controller validation for promoted result-projection slices
- parity-inventory and design-document updates required to keep the supported result-projection surface explicit

**Out of scope**

- additional facet-family widening unless Phase 4 uncovers a shared result-projection contract defect
- full runtime cutover or removal of legacy fallback outside the validated result-projection surface
- route-definition governance, configuration hardening, and broader performance work reserved for later phases
- unrelated controller or API redesign beyond the explicit result-projection handoff

## Risks And Mitigations

| Risk                                                                                                              | Mitigation                                                                                          |
|-------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------|
| `ResultService` currently depends on `QuerySetupBuilder.Build(...)`, which may hide legacy filtering assumptions. | Define the composed handoff contract first and promote one focused result slice at a time.          |
| Tabular and map result formats may diverge in grouping and coordinate semantics once they use composed anchors.   | Validate `TabularResultSqlCompiler` and `MapResultSqlCompiler` separately before grouped promotion. |
| Result payload services may still rely on legacy-only context even after SQL compilation moves.                   | Add focused service-level tests that assert payload behavior independently of controller wiring.    |
| Shared query-setup changes for results could regress the supported facet-content matrix.                          | Re-run the grouped composed facet-content regression after any shared anchor or query-setup change. |
